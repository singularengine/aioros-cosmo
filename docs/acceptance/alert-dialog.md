# Alert Dialog

shadcn/ui's `alert-dialog` (Radix AlertDialog) as `c:AlertDialog`: the dialog's surface with the `alert` class (shadcn's
`AlertDialogContent`, `sm` its small size), no close button, a click on the mask that does not close it, the focus on
its cancel button (`IsCancel="True"`, shadcn's `AlertDialogCancel`) and Escape closing it.

| AC | Criterion |
| --- | --- |
| ALERTDIALOG-01 | Given the `alert-dialog-open` fixture on the desktop in each theme (a 640 by 360 host), when its trigger opens it, then the surface resolves shadcn/ui's `AlertDialogContent` background, border, 10 px radius, 24 px padding and `shadow-lg`, 512 px wide and centered (the reference's box within 0.5 px horizontally and 2.5 px vertically), the title is 18 px semibold on a 28 px line with the description 6 px below it, the footer's Cancel and Continue sit at the end 8 px apart (within 1.5 px), there is no close button, and with the `sm` class the surface is 320 px wide. |
| ALERTDIALOG-02 | Given an open alert dialog on the desktop, when it opens, then the focus is on its cancel button; a click on the mask leaves it open; Escape closes it with the focus back on its trigger; and its Continue button (`c:Dialog.Closes`) closes it. |
| ALERTDIALOG-03 | Given a view whose model asks for a confirmation by a command awaiting the alert dialog's answer (`IsOpen` bound two way), when the trigger runs it on the desktop and Continue is clicked, then the command resumes with `continue` and the dialog is closed; asked again, Cancel resumes it with `cancel`. |
| ALERTDIALOG-04 | Given the Alert Dialog page on the web, when the trigger is pressed in Chromium, then the answer opens the page's `<dialog class="prompt" role="alertdialog">` (written closed with the page, `a:Web.Modal`) as a modal holding the alert's title, description and its two answers as buttons, with no close button; Escape closes it in the browser as Radix's does, posting its bound `IsOpen` so that the answer shows the model's closed outcome; pressing Continue in the reopened dialog posts and the answer closes it and shows the model's outcome. |
| ALERTDIALOG-05 | Given the `alert-dialog-open` fixture on the desktop, when the alert dialog opens, then its surface is shown at opacity 0 and 95% from its center, over 200 ms with `ease`, and is at rest once 200 ms have passed, and in a window with `c:Motion.IsReduced` it opens at rest, nothing moving. |
| ALERTDIALOG-06 | Given the Alert Dialog page on the web, when the visitor opens it (a post), then its surface has the `@starting-style` `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, 0)` and its opacity and transform transitions over 0.2 s with `cubic-bezier(0.25, 0.1, 0.25, 1)`, its mask fades in, and while the `<dialog>` is closed its surface's look is `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, 0)` over 200 ms and its mask's opacity 0 over 150 ms, the dialog kept displayed and in the top layer for 200 ms (`display` and `overlay` `allow-discrete`, none of it for a visitor who asks for less motion), so it leaves as shadcn/ui's `animate-out` |
| ALERTDIALOG-07 | Given the Alert Dialog page's "Opened in the browser" example on the web, whose `Trigger` is its `Discard draft` button and whose `IsOpen` is not bound, when `Discard draft` is clicked, then with no request the alert dialog opens as a modal `<dialog>` with the focus inside it; Escape closes it and the focus returns to `Discard draft`; reopened, a click outside leaves it open, as Radix's alert dialog; `Keep` (`c:Dialog.Closes`) closes it; still with no request; and while it is closed its content is not in the accessibility tree (Radix's `DialogTrigger` and `DialogClose`; Aioros's `a:Web.Modal`, audit INT-07). |
| ALERTDIALOG-08 | Given the `alert-dialog-open` fixture on the desktop, when the alert dialog closes, then its surface stays, passing clicks through, while it leaves for opacity 0 and 95% over 200 ms with `ease`, and is gone once 200 ms have passed; with `c:Motion.IsReduced` it closes at once. |
