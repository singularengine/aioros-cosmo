# Input

shadcn/ui's `input` as Avalonia's `TextBox` with Cosmo's control theme (`src/Aioros.Cosmo/Forms/TextBox.axaml`), written
as an `<input>` on the web.

| AC | Criterion |
| --- | --- |
| INPUT-01 | Given the `input-states` fixture, when the page is served, then each `TextBox` is an `<input>` with a form field name, its `PlaceholderText` as `placeholder`, its `Text` as `value`, `type="email"` from `a:Web.InputType` and `disabled` when it is not enabled, and a `TextBox` with a `PasswordChar` is an `<input type="password">`. |
| INPUT-02 | Given the `input-states` fixture in the light and the dark theme on the web, when Chromium computes each `<input>`, then its box (x, y, width, 36 px height), text color, background (transparent, the dark `--input` at 30%), border color and width, corner radius (8 px), padding (4 px 12 px), `shadow-xs`, font size (14 px) and weight and opacity (0.5 when disabled) are shadcn/ui's, and its placeholder is painted in `--muted-foreground` |
| INPUT-03 | Given the `input-states` fixture in each theme on the web, when an enabled `<input>` takes the keyboard focus, then its border color is shadcn/ui's focused border (`--ring`) and its box shadow shadcn/ui's 3 px ring with `shadow-xs` |
| INPUT-04 | Given a `TextBox` in each theme on the desktop, when it is shown, focused, invalid (a data validation error), invalid and focused, and disabled, then its border element resolves shadcn/ui's background, border brush and box shadow for that state (`shadow-xs`; the 3 px `--ring` at 50% with `--ring` border when focused; the `--destructive` border, with its 20% (light) or 40% (dark) ring when also focused) within 1/255, its corner radius is 8 px, padding 12 by 4 px, height 36 px, font 14 px, placeholder brush `--muted-foreground`, selection brushes `--primary` and `--primary-foreground`, and a disabled box has an opacity of 0.5. |
| INPUT-05 | Given a `TextBox` whose `Text` is bound two way with a compiled binding on the desktop, when the keyboard types into it, then the view model's property takes the typed text; when the model changes, the box shows the new text; and a bound `IsEnabled` through `BoolConverters.Not` disables it. |
| INPUT-06 | Given the Input page on the web, when a visitor types a name into its two-way bound field and posts the form with the `Greet` button, then the answer has the field's value kept and the greeting `Hello, {name}` written by the command from the bound property. |
| INPUT-07 | Given the `input-file` fixture in each theme on the desktop (an `a:FilePicker` with Cosmo's file input theme), when it is shown, then the picker is a 384 by 36 px box at shadcn/ui's input's place within 1 px, with the input's border, radius and shadow, a medium 14 px "Choose File" 12 px in from its left and "No file chosen" after it, as Chromium draws shadcn/ui's `<Input type="file">`; and choosing a file shows its name in place of "No file chosen". |
| INPUT-08 | Given the same fixture on the web, when Chromium lays it out, then the picker is a `<label>` holding its hidden file input at the same box with the same texts, and choosing `photo.png` writes it in place of "No file chosen" with no request. |
| INPUT-09 | Given an `a:FilePicker` with Cosmo's file input theme, `c:FileInput.ChooseText="Elegir archivo"` and `c:FileInput.EmptyText="Ningún archivo"`, and one without them, when each is shown on the desktop, then the first writes those two texts and the second "Choose File" and "No file chosen" (INPUT-07); when the first holds a file its name replaces the empty text, and when the file is cleared the empty text comes back. Found in a real app under `?culture=es-MX`. Precedent: shadcn/ui's `<input type="file">`, whose texts are the browser's own in the page's language. |
| INPUT-10 | Given the `input-file-texts` fixture on the web (the pickers of INPUT-09), when Chromium lays it out, then the first picker's texts are `Elegir archivo` and `Ningún archivo`, the second's the defaults, and choosing `photo.png` in the first writes it in place of `Ningún archivo` with no request. |
