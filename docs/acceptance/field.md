# Field

shadcn/ui's `field` as Cosmo's `c:Field`, `c:FieldGroup` and `c:FieldSet` (sealed `StackPanel`s), `c:FieldLabel` (a
`Label`), `c:FieldLegend`, `c:FieldDescription` and `c:FieldError` (sealed `TextBlock`s), with the validation errors of
Avalonia's `DataValidationErrors` shown as shadcn's `FieldError` (`src/Aioros.Cosmo/Forms/Field.axaml`,
`DataValidationErrors.axaml`).

| AC | Criterion |
| --- | --- |
| FIELD-01 | Given the `field-form` fixture in each theme on the desktop, when it is laid out, then the box of every part (the group, each field, label, input, description, the legend, the horizontal field's checkbox and label) relative to the group is shadcn/ui's within 2.5 px (Avalonia rounds each measured size up to a whole pixel, so shadcn's 19.25 px label lines take 20 px and the difference adds up down the form), the horizontal field's label filling the row its check box leaves as shadcn's `flex-auto` label does, and the invalid field's label, input text and error are `--destructive`. |
| FIELD-02 | Given the `field-form` fixture in each theme on the web, when Chromium computes it, then every input's box, every label's, description's and the legend's x, font size, weight and color, and the error's font size, line height, color and position (12 px below its field) are shadcn/ui's; the invalid field has `aria-invalid="true"` and its error is the `role="alert"` element its `aria-describedby` names |
| FIELD-03 | Given a `TextBox` bound to a view model implementing `INotifyDataErrorInfo` on the desktop, when the model reports an error for its property, then the box takes the `:error` look (the `--destructive` border) and shows the message 12 px below it in a 14 px `--destructive` text; when the error is cleared, the message and the look go. |
| FIELD-04 | Given the Forms example page on the web, when a visitor posts the form with a title of 3 characters, an invalid email and the terms not accepted, then the answer shows each text field's error message (`Title must be at least 5 characters.`, `Enter a valid email address.`) as the `role="alert"` element its field's `aria-describedby` names and the terms' error (`Accept the terms to send the report.`, a `c:FieldError` bound to the model, since a checkbox's template shows no validation errors) with the field's border in `--destructive`, and the field labels of the invalid fields (`c:Field Classes.invalid` bound to the model) in `--destructive`; when the corrected values are posted with the terms accepted, the errors are gone and the submit command reports the saved values. |
| FIELD-05 | Given a `c:Field` whose `invalid` class is bound to a view model (`Classes.invalid`) on the desktop, when the model's value turns true and back, then the field takes and drops the class and its label's foreground turns `--destructive` and back. |

| FIELD-08 | Given the `field-content` fixture in each theme on the desktop (two horizontal `c:Field`s in a 448 px `c:FieldGroup`: a `c:FieldContent` holding a `c:FieldLabel` and a two-line `c:FieldDescription` beside a `ToggleSwitch`, and one holding a `c:FieldTitle` and a description beside a `CheckBox`), when it is laid out, then every part's box (the fields, the contents, the labels and title, the descriptions, the switch and the check box) relative to the group is shadcn/ui's within 2.5 px: the content takes the row its control leaves less the field's 12 px gap (`flex-1`), the label and title as wide as their text (`w-fit`), 6 px above the description (`gap-1.5`), and the control at the top of the row (`items-start` beside a `FieldContent`), the check box 1 px lower (`mt-px`); a field taller than the row it is laid out in keeps its parts at its top. |
