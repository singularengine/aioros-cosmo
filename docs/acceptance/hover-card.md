# Hover Card

shadcn/ui's `hover-card` (Radix HoverCard) as `c:HoverCard.Card` on any control (`src/Aioros.Cosmo/Overlays/HoverCard.cs`):
the card opens in a `Flyout` whose presenter takes the `hover-card` class (shadcn's `HoverCardContent`: `w-64 rounded-md
border bg-popover p-4 shadow-md`, 4 px below its trigger) after Radix's 700 ms open delay, stays while the pointer is
over the trigger or the card, and closes 300 ms after it left both (`c:HoverCard.OpenDelay`, `CloseDelay`, `Placement`).
Avalonia has no hover card; its `ToolTip` closes as the pointer leaves its control, so the card is a flyout. Aioros does
not write a control's attached flyout on the web (framework need 34).

| AC | Criterion |
| --- | --- |
| HOVERCARD-01 | Given the `hover-card-open` fixture on the desktop in each theme (a link button with a card of an avatar, a title, a text and a muted date, `OpenDelay` 0, `Placement="BottomEdgeAlignedLeft"`, the presenter 320 px wide by an app style), when the pointer rests on the trigger, then the card opens and its border resolves shadcn/ui's `HoverCardContent` background, text color, border, 8 px radius, 16 px padding and `shadow-md`, its box is the reference's within 0.5 px horizontally and 2.5 px vertically, and a card without the app style is 256 px wide (`w-64`). |
| HOVERCARD-02 | Given a control with a card on the desktop, when the pointer enters it with the default 700 ms delay, then the card is not open at once; with `OpenDelay` 0 it opens at once, stays open while the pointer moves from the trigger onto the card and a button in the card can be clicked, and with `CloseDelay` 0 it closes as the pointer leaves both, while with the default 300 ms it is still open just after; Tab onto the trigger opens it and blurring the trigger closes it. |
| HOVERCARD-03 | Given a view whose card content binds the model's user through compiled bindings and a `ContentControl` with a `ContentTemplate`, when the card opens on the desktop, then it shows the model's values in the page's data context, and changing the model updates the open card. |
| HOVERCARD-04 | Given the Hover Card page on the web, when it is served, then each trigger is written as its link or button inside the framework's hover span with Radix's delays (700 ms open, 300 ms close), and its card is written as a `popover="hint"` with `role="dialog"` holding the card's content, closed at rest; hovering the trigger in Chromium opens the card without a request. |
| HOVERCARD-05 | Given the `hover-card-open` fixture on the desktop, when the card opens, then its surface is shown at opacity 0, 95% and 8 px up, its origin at its top center, as tw-animate-css's `animate-in fade-in-0 zoom-in-95` with `slide-in-from-{side}-2` (opacity 0, 95% and 8 px towards the trigger, 150 ms with `ease`, `cubic-bezier(0.25,0.1,0.25,1)`), and is at rest once 150 ms have passed, and in a window with `c:Motion.IsReduced` it opens at rest, nothing moving. |
| HOVERCARD-06 | Given the `hover-card-open` fixture on the web, when Chromium reads the card's `popover="hint"`, then its `@starting-style` is `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, -8)`, its look while closed is `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, 0)` with its own 150 ms transitions (tw-animate-css's `animate-out fade-out-0 zoom-out-95`, which leaves without the slide; Cosmo's `:closing` look), its origin is `50% 0%`, and its computed transitions are opacity and transform over 0.15 s with `cubic-bezier(0.25, 0.1, 0.25, 1)`, with `display` and `overlay` as `allow-discrete` (exits through the top layer) |
| HOVERCARD-07 | Given the `hover-card-open` fixture open on the desktop, when it closes, then a picture of its surface stands in the window's overlay layer where the surface stood, passing clicks through, with the surface's transitions (150 ms with `ease`) and its origin at its top center, and leaves for opacity 0 and 95% (tw-animate-css's `animate-out fade-out-0 zoom-out-95`), gone once 150 ms have passed; and in a window with `c:Motion.IsReduced` it closes at once, with no picture. Precedent: Radix's `Presence`, which keeps closed content only while its exit animation plays. |
