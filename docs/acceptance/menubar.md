# Menubar

shadcn/ui's `menubar` (Radix Menubar) as Avalonia's `Menu` with Cosmo's themes: the bar (36 px, a 1 px `--border`
border, an 8 px radius, `--background`, `shadow-xs`, 4 px padding, items 4 px apart), its top-level items (`px-2 py-1`,
medium, `--accent` when open or selected) whose menus open 8 px under them and 4 px before their start (Radix's
`sideOffset` 8 and `alignOffset` -4) at least 192 px wide, their items Cosmo's menu items (shortcuts, separators,
checks, radios, `inset`, submenus).

| AC | Criterion |
| --- | --- |
| MENUBAR-01 | Given the `menubar-demo` fixture in each theme on the web, when the page is served, then it is a `<menu>` toolbar whose File, Edit, View and Profiles buttons open anchored popover menus (without a request) holding the items, their shortcuts, separators, the checked item and the chosen radio, with the bar's box, border, radius and background as shadcn/ui's; the top-level items' 8 px padding, the menus' 8 px offset, -4 px alignment, width and shadow are Aioros's (framework need 54). |
| MENUBAR-02 | Given the `menubar-demo` and `menubar-open` fixtures in each theme on the desktop, when they are shown and File is clicked, then the bar is at shadcn/ui's box within 1 px (36 px, 1 px `--border` border, 8 px radius, `shadow-xs`), the top-level items are at shadcn/ui's boxes within 2.5 px (28 px high, text widths rounded up to whole pixels) in medium text, File is `--accent`, and its menu is 192 px wide, 8 px under File and 4 px before its start, with a 1 px border, an 8 px radius, `shadow-md` and its items 32 px high. |
| MENUBAR-03 | Given the `menubar-demo` fixture on the desktop, when the user opens File and presses Right, then Edit's menu is open and File's closed; Left goes back to File with its first item focused (Radix focuses a menu's first item when the keyboard opens it); Down moves to the second item; and Escape closes the menu. |
| MENUBAR-04 | Given a view whose menubar binds its items' commands with parameters and a checkable item's `IsChecked` two way (compiled bindings, no code-behind), when the user clicks the checkable item, then the model's flag is set, when the model clears it the item is unchecked, and when the user clicks a command item, the model records its parameter. |
| MENUBAR-05 | Given the Menubar page on the web, when a visitor posts an item of the bound menubar, then the answer reads the model's last action as that item's. |
| MENUBAR-06 | Given the `menubar-demo` fixture on the desktop, when its first menu opens, then the menu's surface is shown at opacity 0, 95% and 8 px up, its origin at its top start, as tw-animate-css's `animate-in fade-in-0 zoom-in-95` with `slide-in-from-{side}-2` (opacity 0, 95% and 8 px towards the trigger, 150 ms with `ease`, `cubic-bezier(0.25,0.1,0.25,1)`), and is at rest once 150 ms have passed, and in a window with `c:Motion.IsReduced` it opens at rest, nothing moving. |
| MENUBAR-07 | Given the `menubar-open` fixture on the web, when Chromium reads the first menu's popover, then its `@starting-style` is `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, -8)`, its look while closed is `opacity: 0; transform: matrix(0.95, 0, 0, 0.95, 0, 0)` with its own 150 ms transitions (tw-animate-css's `animate-out fade-out-0 zoom-out-95`, which leaves without the slide; Cosmo's `:closing` look), its origin is `0% 0%`, and its computed transitions are opacity and transform over 0.15 s with `cubic-bezier(0.25, 0.1, 0.25, 1)`, with `display` and `overlay` as `allow-discrete` (exits through the top layer). |
| MENUBAR-08 | Given the `menubar-demo` fixture on the desktop with its first menu open, when it closes, then a picture of its surface stands in the window's overlay layer where the surface stood, passing clicks through, with the surface's transitions (150 ms with `ease`) and its origin at its top start, and leaves for opacity 0 and 95% (tw-animate-css's `animate-out fade-out-0 zoom-out-95`), gone once 150 ms have passed; and in a window with `c:Motion.IsReduced` it closes at once, with no picture. Precedent: Radix's `Presence`, which keeps closed content only while its exit animation plays. |
