# Button

shadcn/ui's `button` as Avalonia's `Button` (and `HyperlinkButton`) with Cosmo's control theme
(`src/Aioros.Cosmo/Buttons/Button.axaml`): variants and sizes are classes. The reference is shadcn/ui's render of the
same fixtures in Chromium (`tools/shadcn/out`, fixtures in `tools/shadcn/app/src/fixtures.tsx` and the Gallery's
`/fidelity/*` pages).

| AC | Criterion |
| --- | --- |
| BUTTON-01 | Given a Cosmo `Button`, when the page is served, then it is a real `<button type="submit" name="_btn">` holding its text (or its icon and text), with `disabled` when it is not enabled, and an icon-only button carries its `AutomationProperties.Name` as `aria-label`. |
| BUTTON-02 | Given a `Button` of each variant (default, `destructive`, `outline`, `secondary`, `ghost`, `link`) in the light and the dark variant on the desktop, when it is shown and when it is under the pointer (`:pointerover`), then its resolved background, foreground and border (brush and thickness) are the colors Chromium computes for shadcn/ui's button of that variant in that state (`button-variants`), within 1/255 per channel. |
| BUTTON-03 | Given the `button-variants` fixture in the light and the dark theme on the web, when Chromium computes each `<button>`'s style, then its background, color, border color and width, corner radius, font size and weight and height are shadcn/ui's for that variant; in the `button-disabled` fixture each `<button>` is also `disabled` with an opacity of 0.5, as shadcn's. |
| BUTTON-04 | Given the `button-sizes`, `button-extra-sizes` and `button-icons` fixtures (sizes `sm`, default, `lg`, `icon`, the extra sizes `xs`, `icon-xs`, `icon-sm` and `icon-lg`, and `has-icon` buttons with a Lucide icon before or after their text), when they are rendered on the web, then each button's box (x, y, width, height relative to the fixture) is shadcn/ui's within 0.5 px. |
| BUTTON-05 | Given the `button-variants` fixture in each theme on the web, when the pointer is over each button, then its computed background and color are those of shadcn/ui's button in its hover state (`bg-primary/90`, `hover:bg-accent`, `dark:hover:bg-input/50`…). |
| BUTTON-06 | Given a `Button` of the default, `destructive` and `outline` variants on the desktop, when it has the keyboard focus (`:focus-visible`), then its presenter shows shadcn's ring: a 3 px spread `BoxShadow` of `--ring` at 50% (`--destructive` at 20% in light and 40% in dark for `destructive`; with the outline's shadow-xs kept), and its border brush `--ring` (`--input` in dark for `outline`). |
| BUTTON-07 | Given a disabled `Button` of each variant, when it is shown on the desktop and the mouse clicks it, then its opacity is 0.5, it never gets `:pointerover`, and its command does not run. |
| BUTTON-08 | Given a `Button` whose content is a `StackPanel` of an icon and a text, when it is shown on the desktop, then the panel is horizontal with shadcn's gap (8 px, 6 px with `sm`, 4 px with `xs`) unless the panel sets its own, and `has-icon` gives the padding shadcn uses for `has-[>svg]` (12 px, 10 px with `sm`, 16 px with `lg`, 6 px with `xs`). |
| BUTTON-09 | Given a `HyperlinkButton` with `NavigateUri="/components/badge"` and no class, and one with `Classes="outline lg"`, when the page is served, then each is an `<a href>` to its address with the look of a `Button` of the same classes (background, color, border width, height, padding and corner radius), as shadcn's `<Button asChild>` around a link; the outline link's border color is not written yet (a framework need, see the decisions). |
| BUTTON-10 | Given the `button-variants` fixture in each theme on the web, when each button takes a visible keyboard focus, then Chromium computes shadcn/ui's focus ring for it: the 3 px `--ring` at 50% box shadow (`--destructive` at 20% or 40% for `destructive`, with the `shadow-xs` kept for `outline`) and the `--ring` border color where the variant has a border, and no outline of the browser's own. |
| BUTTON-11 | Given the `button-variants` fixture on the web, when Chromium computes the buttons, then each has shadcn/ui's `transition-all` as a 150 ms `cubic-bezier(0.4, 0, 0.2, 1)` transition of its background, border, text color and shadow, the `outline` button has shadcn/ui's `shadow-xs` at rest, and the `link` button has no text decoration at rest and is underlined under the pointer. |
| BUTTON-12 | Given the `button-invalid` fixture in each theme on the desktop (an outline `Button` with an error, `DataValidationErrors.Error`, an outline `Button` that is the control of a `c:Field` with the `invalid` class, and a default `Button` with an error), when they are shown and when each takes the keyboard focus, then each button keeps shadcn/ui's box within 1.5 px (an error shows no message: a button's template has no `DataValidationErrors`), the outline buttons' border is `--destructive` (shadcn/ui's `aria-invalid:border-destructive`), the default button keeps no border, and each focus ring is `--destructive` at 20% (40% dark), with the outline's `shadow-xs` kept, as shadcn/ui's `aria-invalid:ring-destructive/20`. |
| BUTTON-13 | Given the `button-invalid` fixture in each theme on the web, when Chromium computes the buttons at rest and with a visible keyboard focus, then each keeps shadcn/ui's box within 1 px and no message is written for its error, and their border color and width and their focus ring are shadcn/ui's for `aria-invalid="true"`, as BUTTON-12 states for the desktop. |
| BUTTON-14 | Given the `button-extra-sizes` fixture in each theme on the desktop (`xs` with a text and with an icon, `icon-xs`, `icon-sm`, `icon-lg`, plain and outline), when it is laid out, then each button's size is shadcn/ui's within 1 px and its place within 2 px (Avalonia rounds each width up to a whole pixel, which adds up along the row; 24 px high for `xs` with 8 px of padding, 6 px beside an icon; 24, 32 and 40 px squares for the icon sizes) and an `xs` or `icon-xs` button gives the icons inside it 12 px (`IconStyle.Size`, shadcn/ui's `[&_svg]:size-3`) where every other size leaves the 16 px default. |
| BUTTON-15 | Given the Button page's sizes example on the web, whose `icon-xs` button holds an `a:Icon` without a size and whose `icon-sm` button holds one too, when it is served, then the first icon is written 12 px (`width="12"`) and the second 16 px, as shadcn/ui's `size-3` icon in its `icon-xs` button. |
| BUTTON-16 | Given the `link-content-alignment` fixture on the web (`HyperlinkButton`s stretched to their cell, a ghost one and a default one with `HorizontalContentAlignment="Center"`, and one with `Left`), when Chromium lays them out, then the text of the first two is centered in its link within 1 px, and the third starts at its link's left padding, as Avalonia lays them out. Found in a real app's heat map, whose amounts became left-aligned once wrapped in links. |
