# Select and Native Select

shadcn/ui's `select` (Radix Select) and `native-select` as Avalonia's `ComboBox` with Cosmo's control theme
(`src/Aioros.Cosmo/Forms/ComboBox.axaml`): the trigger is shadcn's `SelectTrigger` (`Classes="native"` places the chevron
as `NativeSelect` does, `sm` is the small size), the drop-down is shadcn's `SelectContent`, `ComboBoxItem` is
`SelectItem`, and the `label` and `separator` item classes are `SelectLabel` and `SelectSeparator`. On the web Aioros
writes a native `<select>`, which is exactly shadcn's `NativeSelect` element.

| --- | --- |
| NATIVESELECT-01 | Given the `native-select` fixture, when the page is served, then each `ComboBox` is a `<select>` with a form field name and an `<option>` per item, the selected item's option `selected`, and the disabled `ComboBox` `disabled`; and on the Select page, posting another option of the `ComboBox` two-way bound to `SelectedItem` makes the answer show the newly selected value |
| NATIVESELECT-02 | Given the `native-select` and `select-trigger` fixtures in each theme on the web, when Chromium computes each `<select>`, then its box within 1 px (36 px high, 32 px with `sm`), border color and width, corner radius, background, font size and weight, text color (the placeholder's `--muted-foreground` included) and the 0.5 opacity of a disabled one are shadcn/ui's (the wrapper's opacity for `NativeSelect`), and each `native` one keeps the browser's own list (`appearance:none`, Aioros's `a:Web.NativeList`) while the others take the customizable select (`appearance:base-select`) |
